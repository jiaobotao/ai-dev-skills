# AI 交付 Skills：SDD 工程流水线 & FDE 现场快闪

一套给 AI 编码助手使用的交付方法论 skill（技能包），把"靠感觉聊天式开发"变成两套有规则、有门禁、有取舍的工作流。两者互为快慢两条轨道：

| Skill | 场景 | 时间尺度 | 交付物 |
|---|---|---|---|
| **[sdd-ai-dev-pipeline](sdd-ai-dev-pipeline/)** | 正式开发：功能、模块、完整项目（企业级 / MVP 双档） | 天～周 | 可上线的代码 + Spec 逻辑产物（四文档，小型可合并）+ 评审记录 |
| **[fde-flash-demo](fde-flash-demo/)** | 客户现场验证一个想法的演示件 | 20–30 分钟 | 能点能演的原型 + 客户真实反应 |

核心分工：**快闪负责"值不值得做"，流水线负责"稳稳做出来"。** 快闪现场客户一旦说"接真数据/要上线/交付吧"，自动升级到流水线走原型转正（SOP 12），默认不在原型代码上续建。

## 方法论一览

**sdd-ai-dev-pipeline（v3.1）**

- 意图路由 12 条 SOP；企业级 / MVP 双档，Spec 逻辑产物（分析/需求/设计/任务）任何档位不可省，小型任务允许合并文档。
- 十七条铁律：文档不批代码不动、文档是单一事实源、门禁不可跳过、AI 实现阶段不做技术决策、产出归 docs/、阻断必配回归并由原专家复审、mock 全绿≠可交付、断点接续先读文档、前端页面先与用户确认、修复先答四问走最小闭环、禁止弱化断言换绿灯且验收只认真实证据、按任务依赖连续执行且无依赖可并行、保护工程现场不碰无关改动、外部副作用不确定先查后动、同版本同范围不重复验证、缺陷修复分级验证、最终交付完整验证与一致性检查。
- 来自真实项目复盘的硬化机制：状态字段生命周期表 + 控制信号×状态矩阵、流式响应错误路径、"回退即红"回归与变异抽查、假绿反模式清单、T1 环境对账、真实联调门禁（≥3 正常 +1 高风险真实场景，含真实拒绝执行与审计落库）。
- v2.2 新增：测试隔离硬规则（独立临时环境、mock 必清、单跑/随机/重复一致）、分层验证阶梯（快速/提交/验收）、导入边界自动检查、CONVENTIONS 必备四节。
- v2.3 新增：执行路线分流（新功能/Bug 修复/线上事故不重复写四文档）、阶段批量连续执行、任务风险分级 R1/R2/R3 与评审强度匹配、需求-实现-测试追溯矩阵、变更影响分析与分级重审、工程现场保护、外部副作用不确定结果处理。
- v2.4 修正：门禁按层递进（任务只跑针对性、全量放阶段末、R3 当下验）、工作区隔离默认不 stash 优先 worktree、探索实验与正式实现分离、专家评审增加"无法判定"第三态；顶部加版本历史表。
- v2.5 演进：人工介入收敛为三关口（启动/决策边界/交付），默认每阶段仅两次人工确认；四文档改评审包合并审批；普通失败先自主诊断修复、按上限升级；R1 自主、R2 自查、R3 严审。
- v2.6 修正：档位差异改为门禁强度而非确认次数、决策分级表厘清自主与暂停边界、异常自愈加有效重试与成本上限、前端 A/B 分级确认、阶段职责不重叠、大型项目按模块分批交付。
- v3.0 优化：按风险选择流程档位、逻辑文档保留但小型任务可合并、测试四级执行（任务/阶段/交付/真实环境）、同版本同范围验证证据复用、专家按影响范围动态调度不设固定人数、缺陷修复分级验证（高风险独立复审+变异验证）、无依赖任务并行与冲突协调、最终交付必须取得当前提交完整证据并完成需求/架构/验收一致性检查。
- v3.1 治理补齐：重大架构决策使用 ADR（有状态、可推翻、Spec 引用，简单项目可 N/A 并说明理由）；交付前执行独立 Converge 收敛门禁（7 项检查、复用当前提交证据，产出 CONVERGENCE.md）。Batch 2/2.1 接入全局唯一 Requirement ID/TEST ID 与 REQ→ADR→TASK→TEST→EVIDENCE 多对多、双向追溯，EVIDENCE 锚定真实验证记录；Constitution 与 Engineering Conventions 分层（企业独立/MVP 合并）并进入接续、Validator 与 Converge 第 4/5 项；Converge 第 3/7 项校验完整追溯链，正式收敛要求干净工作区 + 确定 SHA。

**fde-flash-demo**

- 五节点时间盒：定靶（一句话假设 + 三幕剧本）→ 竖切（单纵切面，MOCK 集中）→ 擦亮（强制 5–8 分钟，行业感假数据 + 高潮瞬间）→ 30 秒自检（金色路径/一键重置/无真实凭据/明示原型）→ 演示收网（三句话反馈）。
- 五条微型铁律：不接生产、不用真实敏感数据、可重复演示、flash/ 沙盒物理隔离、明示验证件身份。
- 默认用完即弃；"要真就转正"有固定回应模板与升级闸门。

## 安装

### Claude 桌面版（Cowork，推荐）

将本仓库两个 skill 目录中的 `SKILL.md` 内容通过"保存技能"分别保存为名为 `sdd-ai-dev-pipeline`、`fde-flash-demo` 的技能即可；技能保存在账户中，跨会话、跨设备生效。

### Claude Code（本地手动安装）

```bash
git clone https://github.com/jiaobotao/ai-dev-skills.git ~/ai-dev-skills   # 私有仓库，需你的 GitHub 账号有权限
mkdir -p ~/.claude/skills
cp -R ~/ai-dev-skills/sdd-ai-dev-pipeline ~/.claude/skills/
cp -R ~/ai-dev-skills/fde-flash-demo     ~/.claude/skills/
```

两个目录内的 `SKILL.md` 已带 YAML frontmatter（name/description），Claude Code 启动时会自动识别。升级时重新 `git pull` 并复制覆盖即可。

### 其他支持 SKILL.md 的 AI 编码工具

任何按"目录 + SKILL.md + frontmatter"约定加载技能的工具均可直接使用这两个目录，技术栈无关。

## 快速上手

- 要正式开发一个功能/项目：对助手说"用 sdd 流程做 X"，它会先判定档位（企业级/MVP）与流程强度，产出逻辑产物并以评审包合并审批，批准后按依赖连续实施。
- 在客户现场临时要做一个验证性亮点：说"用快闪流程做 X"，它会先和你对齐一句话假设与三幕剧本，20–30 分钟内交付可演原型。
- 新会话继续一个做了一半的项目：流水线 skill 的**断点接续协议**会强制先读文档、输出"接续确认"，经你确认后再动手。

## 隐私与安全

- 技能本身不含任何客户数据、密钥或真实项目代码。
- 两条工作流均内置安全基线：密钥只走 .env 且不入库、测试零外部调用、前端禁裸 innerHTML、日志禁会话正文；快闪流程额外强制物理隔离与现场数据不留存。
