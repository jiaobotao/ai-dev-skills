# sdd-ai-dev-pipeline

Spec 驱动的 AI 自动开发流水线：把 AI 从"每次从零开始的聊天机器人"变成"有规则、有流程、有专家、有记忆的工程化流水线"。技术栈无关。

- 当前版本：**v3.1**
- 类型：正式工程交付流程（企业级 / MVP 双档）
- 姊妹技能：[fde-flash-demo](../fde-flash-demo/)（现场 20–30 分钟演示件）

## 什么时候用

真要做一个功能、模块或完整项目——无论企业级上线还是个人 MVP——需要文档、测试、评审与交付闭环时。明确"先写个 demo 不管质量"的现场场景不要用本技能，用 fde-flash-demo。

## 它会怎么工作

```
0. 意图识别 → 12 条 SOP 路由（声明档位 + 执行路线分流 + 按风险选择流程）
1. Spec 逻辑产物：01-analysis → 02-requirements → 03-design → 04-tasks（小型任务可合并为一份；评审包合并审批【关口 1】，含唯一 Requirement ID/TEST ID 与 REQ→ADR→TASK→TEST→EVIDENCE 多对多、双向追溯矩阵）
2. T1 环境对账 → 按依赖连续实施（无依赖并行、有冲突协调；只在决策边界暂停；测试分四级：任务/阶段/交付/真实环境）
3. 三层 Validator 自检（编码规范 / 合规安全 / 架构约束；同版本同范围有效证据可复用）
4. 专家 Agent 并行评审（按影响范围与风险动态调度，不设固定人数）→ 缺陷修复分级验证 → 原专家复审（高风险另加独立复审与变异验证）
5. 交付级完整验证（当前提交全量测试 + Lint + Type Check + Build + 需求/架构/验收一致性检查）+ 按风险真实联调 → Converge 独立收敛门禁（须干净工作区 + 确定 SHA；核对 Constitution 与完整追溯链；7 项检查 / CONVERGENCE.md）→ 人类终审【关口 3】
6. 沉淀归档、复盘、记忆，跨项目教训回流改本技能
```

重大架构、数据模型、权限、安全或关键技术路线决策使用 `docs/adr/` ADR 管理（状态流转、推翻建新不覆旧，Spec 引用；简单项目可标 N/A 并说明理由）。ADR 合并进已有审批关口，不新增人工确认。项目长期原则放 `CONSTITUTION.md`（企业级独立；MVP 并入 `ENGINEERING-CONVENTIONS.md` 的 Constitution 原则章节），并在接续、Validator 与 Converge 第 4/5 项核对；追溯矩阵支持 REQ/ADR/TASK/TEST/EVIDENCE 多对多、分号多值与反向查询，EVIDENCE 必须锚定真实验证记录（SHA + 命令输出/评审路径），不得只填 Pass。

十七条铁律贯穿全程，要点：文档不批不动代码；任何变更先改文档再改代码；阻断必须配"回退即红"回归并由原打回专家复审；mock 全绿不算完，必须真实联调；新会话接旧项目先执行断点接续（小 Bug 可走轻量接续）；前端页面细节先经用户确认再进设计；修复先答四问并走最小闭环；测试必须隔离、mock 必清；禁止弱化断言换绿灯，验收只认命令退出码/用例数/覆盖率等真实证据；规格批准后按依赖连续执行、无依赖任务可并行、只在决策边界暂停；保护工作区不碰无关改动；外部副作用超时先查后动、不确定不重试；同一版本同一范围不重复验证；缺陷修复必须有回归测试，高风险另加独立复审与变异验证；最终交付必须取得当前提交的完整证据并完成需求/架构/验收一致性检查，跳过项说明原因、失败不得伪装通过。

## 典型使用示例

- "用 sdd 流程做一个本机对话式决策助手" → 判定 MVP 档，产出逻辑产物并以评审包一次性与你确认，批准后连续实施。
- "继续把上个项目做完"（新会话）→ 触发断点接续：读四文档/评审/ISSUES/git log，输出接续确认，你点头后才编码。
- "给这个系统加导出 Excel 功能" → SOP 5 代码开发：先补需求与设计章节，再写实现与测试。
- 客户看完快闪原型说"就按这个上线" → SOP 12 原型转正：重新过四文档，原型默认不作为正式代码基底。

## 产物清单（在目标项目中）

```
docs/
  CONSTITUTION.md 长期原则（企业级独立；MVP 并入 ENGINEERING-CONVENTIONS.md 的 Constitution 原则章节）
  specs/<模块>/ 01-analysis.md 02-requirements.md 03-design.md 04-tasks.md
                 SPEC-TASK.md（小型任务合并产物）ISSUES.md  APPROVED.md  TRACEABILITY.md
  adr/           重大架构决策（状态流转，推翻建新不覆旧；可 N/A）
  reviews/       专家初审+复审全过程 + EVIDENCE 验证记录归档
  CONVERGENCE.md Converge 收敛判定（须干净工作区 + 确定 SHA）
  ENGINEERING-CONVENTIONS.md  LESSONS-LEARNED.md  MANUAL-CHECKLIST
```

## 版本来源

本技能的 v2 机制全部来自一个真实项目（LangGraph + FastAPI 本机决策助手）的首轮实跑复盘：97% 测试覆盖率下专家仍抓出 8 个阻断，首轮修复又引入 3 个新阻断——因此有了强制复审、回归测试与变异抽查；v2.1 的断点接续与前端确认来自跨会话续作的真实断点；v2.2 的修复闭环四问、测试隔离、分层验证与"只认真实证据"来自第二次实跑中反复出现的测试结构/mock 污染/导入问题；v2.3 的阶段连续执行、风险分级、变更治理、工作区保护与副作用不确定结果处理，来自"严谨但空转"的复盘——核心是控制何时必须停、何时应继续。v3.0 聚焦执行效率与测试优化：按风险选流程、文档保留但可合并、测试四级、证据复用、专家动态调度、缺陷修复分级验证、依赖驱动并行与最终完整验证。v3.1 补齐治理层（ADR 重大决策管理）与交付收敛层（Converge 独立收敛门禁），Batch 2 接入唯一 Requirement ID、REQ→ADR→TASK→TEST→EVIDENCE 全链追溯、Constitution 分层与“干净工作区 + 确定 SHA”收敛前置条件；Batch 2.1 补齐 Constitution 进入接续/Validator/Converge、多对多双向追溯、TEST ID 规范与 Converge 完整性校验。详见仓库 [CHANGELOG.md](../CHANGELOG.md)。
