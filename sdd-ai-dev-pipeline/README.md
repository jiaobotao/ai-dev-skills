# sdd-ai-dev-pipeline

Spec 驱动的 AI 自动开发流水线：把 AI 从"每次从零开始的聊天机器人"变成"有规则、有流程、有专家、有记忆的工程化流水线"。技术栈无关。

- 当前版本：**v2.1**
- 类型：正式工程交付流程（企业级 / MVP 双档）
- 姊妹技能：[fde-flash-demo](../fde-flash-demo/)（现场 20–30 分钟演示件）

## 什么时候用

真要做一个功能、模块或完整项目——无论企业级上线还是个人 MVP——需要文档、测试、评审与交付闭环时。明确"先写个 demo 不管质量"的现场场景不要用本技能，用 fde-flash-demo。

## 它会怎么工作

```
0. 意图识别 → 12 条 SOP 路由（声明档位）
1. Spec 四文档：01-analysis → 02-requirements → 03-design → 04-tasks（逐份评审）
2. T1 环境对账 → 按任务实施
3. 三层 Validator 自检（编码规范 / 合规安全 / 架构约束）
4. 专家 Agent 并行评审 → 阻断修复 → 原专家复审（含变异抽查）
5. CI/本地等价门禁 + 真实联调（≥3 正常 +1 高风险）+ 人类终审
6. 沉淀归档、复盘、记忆，跨项目教训回流改本技能
```

九条铁律贯穿全程，要点：文档不批不动代码；任何变更先改文档再改代码；阻断必须配"回退即红"回归并由原打回专家复审；mock 全绿不算完，必须真实联调；新会话接旧项目先执行断点接续协议；前端页面细节先经用户确认再进设计。

## 典型使用示例

- "用 sdd 流程做一个本机对话式决策助手" → 判定 MVP 档，产出四文档并逐份与你确认。
- "继续把上个项目做完"（新会话）→ 触发断点接续：读四文档/评审/ISSUES/git log，输出接续确认，你点头后才编码。
- "给这个系统加导出 Excel 功能" → SOP 5 代码开发：先补需求与设计章节，再写实现与测试。
- 客户看完快闪原型说"就按这个上线" → SOP 12 原型转正：重新过四文档，原型默认不作为正式代码基底。

## 版本来源

本技能的 v2 机制全部来自一个真实项目（LangGraph + FastAPI 本机决策助手）的首轮实跑复盘：97% 测试覆盖率下专家仍抓出 8 个阻断，首轮修复又引入 3 个新阻断——因此有了强制复审、回归测试与变异抽查；v2.1 的断点接续与前端确认来自跨会话续作的真实断点。详见仓库 [CHANGELOG.md](../CHANGELOG.md)。
