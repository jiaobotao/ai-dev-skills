# FDE 现场快闪交付（Flash Demo）

在客户面前，用 20-30 分钟把一个想法变成**能点、能看、能引发反应**的演示件，帮助客户判断"这个想法值不值得往下做"。

核心信念：**现场交付物不是代码，是客户脑子里的一个判断。** 优化目标是单位时间内的客户认知价值，不是工程正确性。糙在背面，亮在正面。

本 skill 之所以敢快，是因为有安全围栏：验证件不接生产、不用真实数据、默认用完即弃。一旦客户想"来真的"，立即路由到 sdd-ai-dev-pipeline。

## 适用与不适用

适用：客户现场/工作坊里临时冒出的想法、售前验证、需求探索、"如果有个功能能 X 会不会很爽"。

不适用（必须走 sdd-ai-dev-pipeline）：任何要上线、接真实客户数据、进正式代码库、谈交付排期、涉及钱或合规的请求。

## 微型铁律（五条，不可违反）

1. **不接生产**：不连生产库/生产 API/真实账号；需要外部能力一律用 mock 或只读沙箱。
2. **不用真实敏感数据**：演示数据自己造，且要造得像真的；不留存任何客户现场数据。
3. **可重复演示**：必须有一键重置（清状态/回到初始剧本起点），演示翻车能立刻重来。
4. **物理隔离**：产出放在独立沙盒目录（如 `flash/<日期-主题>/`），不进正式代码库、不动客户仓库。
5. **明示身份**：开场向客户说明"这是现场验证想法的原型，数据是演示数据"，管理预期，不冒充实物。

## 时间盒：20-30 分钟，五节点

| 节点 | 时长 | 产出 |
|---|---|---|
| 1. 定靶 | 3-5 分钟 | 一句话假设 + 三幕演示剧本（客户口头确认） |
| 2. 竖切 | 10-15 分钟 | 一条贯通的纵切面，能真点真跑 |
| 3. 擦亮 | 5-8 分钟 | 演示数据、亮点瞬间、空态/加载不露怯 |
| 4. 三十秒自检 | ≤2 分钟 | 四项翻车/安全检查 + 一键重置演练 |
| 5. 演示与收网 | 演示中/后 | 三句话反馈记录 + 弃用/转正决策 |

**时间到了没做完的默认动作：用当前版本演，绝不延期继续做。** 一个演出来的半成品胜过一个没见过的完整版。宁可临时删掉做不完的幕，保住三幕中的高潮幕。

### 节点 1：定靶（3-5 分钟）

不写需求文档，只和客户对齐一张"演示剧本卡"，口头确认即开工：

```
要验证的假设（只能一个）：我们相信 <谁> 在 <什么场景> 会因为 <这个功能> 而 <什么行为/付费意愿>。
今天的观众是谁：        （决策者？一线用户？决定演示的语言和深度）
三幕剧：
  开场（看到什么熟悉的东西，30 秒内入戏）：
  操作（客户/你亲手点的 1-3 个关键动作）：
  高潮（那个"哦——"的瞬间，屏幕上出现什么）：
明确不演：              （现场砍掉一切与假设无关的东西）
允许的造假：            （哪些数据/接口是假的，记下来，演示时不露馅）
```

取舍原则：**一个假设、一条路径、一个高潮。** 客户想加第二亮点时，回应："这个记下了，我们先验证最核心的那个，第二个可以作为下一场。"

### 节点 2：竖切（10-15 分钟）

只做一条从输入到结果的贯通纵切面：
- 允许：硬编码、假数据、单用户、无鉴权、无持久化（或内存持久化）、单文件、写死的 happy path。
- 不允许：客户**眼睛能看到、手能点到**的路径是假的——按钮点了没反应、输入框是贴图、高潮结果是提前打开的静态页面。
- 技术选择以"你最快"为唯一标准：单 HTML 文件、Streamlit/Gradio、Notebook、假后台皆可；不引入需要安装调试的新依赖链。
- 结构上留一个明显的 `// MOCK:` / `# MOCK:` 标记区，把所有造假集中，方便节点 5 说明和日后评估转正成本。

### 节点 3：擦亮（5-8 分钟，强制保留，不可被竖切挤占）

现场演示的价值几乎全部在这一节点：
- **数据像真的**：人名、金额、时间用符合客户行业的样例，不用 test1/test2/xxx；数据量体现真实感（列表别只有两行）。
- **设计亮点瞬间**：高潮那一步要有视觉/交互强调（动画、对比、结果卡、"前后"变化），让观众记得住一个画面。
- **不露怯**：加载态有交代（假 loading 也行）、空态有引导、文案完整无 lorem ipsum、无控制台报错、页面不出现报错堆栈。
- **准备好"金色路径"**：你闭眼都能点对的顺序；同时想好客户如果乱点，怎么一句话带回主线。

### 节点 4：三十秒自检（≤2 分钟）

只查会让你现场翻车或违反围栏的四件事，不做代码评审：

1. 把三幕剧从头点一遍，金色路径无断点、无报错；
2. 一键重置有效，重置后能立刻原样再演一遍；
3. 扫一遍：没有真实密钥/内网地址/客户数据；所有外部调用都是 mock（grep MOCK 区之外有无真实 endpoint）；
4. 页面上或你开场白里明确了"演示数据/验证原型"。

### 节点 5：演示与收网

演示时让客户亲手操作关键一步（参与度差一个数量级）；你负责旁白推进节奏。

演完当场记录三句话（写入 `flash/<日期-主题>/FEEDBACK.md`）：

```
客户最真实的反应（原话/表情/追问了什么）：
这个假设被验证了吗：成立 / 不成立 / 还需要验证 <下一个假设>
下一步：用完即弃 / 转 sdd-ai-dev-pipeline 正式立项 / 再做一场快闪验证 <X>
```

默认归宿是**用完即弃**：原型是耗材，验证结论才是产出。

**自动升级闸门**——客户说出以下任一类话时，停止承诺现场实现，明确切换：
- "能不能接我们的真实数据 / 真实系统？"
- "这个明天/下周能不能上线用？"
- "就按这个做，给我们交付吧。"

回应模板："这个反应正是我们今天想验证的。要走到能用的版本，我会用正式的工程流程把它重新做一遍——包含需求文档、数据安全和测试，今天这个原型的价值是帮我们确认了方向。"随后在 sdd-ai-dev-pipeline 中走 SOP 1（需求调研）/ SOP 12（原型转正），以验证过的假设和三幕剧本为输入；**默认不在原型代码上续建**（除非评估 MOCK 区极小、代码质量达标，并记录理由）。

## 沙盒目录约定

```
flash/2026-09-20-智能排产亮点/
  README.md        # 一段话：假设、三幕剧、如何运行、MOCK 清单
  FEEDBACK.md      # 节点 5 的三句话
  app.*            # 原型本体，怎么快怎么来
```

沙盒目录应在正式代码库的 .gitignore 之外或独立仓库；快闪结束后按客户约定删除或归档，不留真实数据。

## 反模式（看到自己在做就喊停）

- 开始搭目录结构、写数据层抽象、配 CI——你在偷跑正式流程。
- 想把三个亮点都做出来——砍到一个。
- 竖切超时就挪用擦亮时间——宁可少一幕，高潮不能糙。
- 客户要真数据时想"就接一下试试"——这是围栏，触发即切换流程。
- 演示前还在改代码——冻结，用三十秒自检代替。

## 执行口诀

**一个假设、三幕剧本；竖切一条、造假集中；背面可糙、正面必亮；三十秒检、一键重来；演完收网、要真就转正。**
